## 网页图片加载（网络实测）

同一张 Files 图（原图 900 × 1125）按不同宽度请求的实际响应（2026-11-17，curl 下载后用 Pillow 量尺寸）：

| 请求 | HTTP | 返回尺寸 |
|---|---|---|
| 无 width | 200 | 900 × 1125 |
| width=250 | 200 | 250 × 313 |
| width=700 | 200 | 700 × 875 |
| width=900 / 1000 / 1400 | 200 | 900 × 1125（超过原图时返回原图，不放大） |

所以之前“请求超过原图会回退到 250px”的判断是错的。真正的问题是 srcset 把 900px 的图标成了 1000w 和 1400w；浏览器按描述的宽度计算，`naturalWidth` 因此显示为约 250（CSS 像素），实际下载的仍是 900px 原图。已改为 srcset 只列不超过原图的宽度。

换上 1600 × 2000 的新图后，在 iPhone 13（3 倍屏）、iPhone SE（2 倍屏）和桌面 1440 下复查：6 个 `<img>` 都在 DOM 里，`complete` 为 true，所有请求 HTTP 200；srcset 为 800w/1600w，iPhone 13 下载 1600 宽，iPhone SE 下载 800 宽；页面没有横向滚动。之前手机上的空白在 Chromium 模拟里没能复现，请在真机上再看一次。
